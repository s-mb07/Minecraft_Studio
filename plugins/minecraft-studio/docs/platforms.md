# Platforms: Modrinth vs CurseForge

Decide this in the brief: it changes which mods you can use and how the pack ships.

| | Modrinth (`.mrpack`) | CurseForge (zip + `manifest.json`) |
|---|---|---|
| Mod lookup | open API, no key: `modrinth.py` | API needs a free key from console.curseforge.com |
| Pack file | references files by URL + sha512 | references files by `projectID` + `fileID` |
| Allowed download hosts | cdn.modrinth.com, github.com, raw.githubusercontent.com, gitlab.com | CurseForge only |
| Launchers | Modrinth App, Prism, ATLauncher, MultiMC forks | CurseForge app, Prism, ATLauncher |
| Status in Minecraft Studio v0.1 | **fully automated** (resolve, audit, build, server test) | documented, manual (planned for v0.2) |

## Mods that are CurseForge-only
Some big ecosystems publish only on CurseForge. Notably the **FTB mods** (FTB Quests, FTB Library, FTB Teams,
FTB Chunks...), which also have no open licence (so no copying their jars into overrides or server packs).

Consequences:
- A Modrinth `.mrpack` cannot include FTB Quests. Options:
  1. Vanilla advancements as quests (datapack, works everywhere), see `mc-quests-ftb` → fallback.
  2. A quest mod hosted on Modrinth (search `modrinth.py search "quests" --mc <v> --loader <l>`, check maturity).
  3. Ship the pack on CurseForge instead.
- The FTB Quests SNBT files generated by `quests.py` are your own content: they go in `overrides/` on any platform.

## Making a CurseForge pack today (manual route)
1. Build and test the pack with Minecraft Studio (Modrinth mods), then in **Prism Launcher** add the CurseForge-only
   mods to the instance from Prism's CurseForge browser.
2. Export from Prism: *Edit instance → Export → CurseForge*. Prism maps mods to CurseForge IDs; mods missing on
   CurseForge are reported and must be replaced or shipped in overrides (only if their licence allows it).
3. Run `validate.py` on the overrides and re-test the exported zip once by importing it.
